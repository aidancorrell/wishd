# Configuration

## Rename compatibility

The product is **wish:d**, short for **what is happening:data**. The installable distribution
and preferred command are `wishd`. The `dataspine` command remains an alias; the Python module
is still `dataspine` so existing scripts and frontend work continue to import it.

All application settings accept `WISHD_*` or their existing `DATASPINE_*` names.
`WISHD_*` wins when both are set, including when its value is empty. Avoid setting both forms.
The CLI reads these keys from `.env` in the current directory. Exported settings take precedence
over either spelling in the file; use the preferred name consistently when migrating. Direct ASGI startup
expects exported configuration; use `wishd serve` for `.env` loading and the bind guard.

Existing database and Compose project names, `.dataspine/artifacts`, S3 object prefixes,
`dataspine_*` metrics, and browser cookies keep their names. The Docker artifact directory
is `/var/lib/wishd/artifacts`, mounted as a persistent named volume. Back up and copy artifacts
from an older container before replacing it; an old container's writable layer is not a volume.

The source repository is `aidancorrell/wishd`. Package registries and domains are a separate
decision from the repository name; see [releasing](releasing.md) for what has actually been
published.

## Core settings

| Setting | Default | Purpose |
|---|---|---|
| `WISHD_DATABASE_URL` | required | PostgreSQL connection URI; use a dedicated database. |
| `WISHD_API_TOKENS` | empty | Comma-separated shared secrets, optionally `label:secret`. |
| `WISHD_ALLOW_INSECURE` | off | Explicitly bypass the CLI's unauthenticated bind guard. |
| `WISHD_BASE_URL` | empty | External HTTPS URL used in notifications and handoff links. |
| `WISHD_POOL_SIZE` | `10` | Maximum connections per gateway process. |
| `WISHD_INGEST_ASYNC` | `true` | Queue events before writing; `false` commits before acknowledging. |
| `WISHD_MAX_BODY_BYTES` | `16777216` | Request limit; lineage uses its producer-friendly refusal response. |
| `WISHD_ARTIFACT_MAX_BYTES` | `67108864` | Maximum content size per artifact. |
| `WISHD_ARTIFACT_DIR` | `.dataspine/artifacts` | Local persistent artifact storage; image uses `/var/lib/wishd/artifacts`. |
| `WISHD_ARTIFACT_S3_BUCKET` | empty | Store artifacts in S3 instead of local disk; requires AWS extra and IAM. |
| `WISHD_MIGRATIONS_DIR` | packaged SQL | Explicit override for migration files. |

Tokens have full read/write access. Generate at least 24 random bytes, for example with
`openssl rand -hex 24`. Send only the secret as `Authorization: Bearer SECRET`, not its label.
Never commit `.env`, raw producer logs or real tokens. Files generated by `make env` are
owner-readable only; the command does not print credentials.

## Docker Compose

Compose explicitly forwards database/auth configuration. Add other application settings to
the gateway's `environment` in a local Compose override; merely adding them to the host `.env`
does not make them appear inside a container. Keep that override and its secrets out of Git.
For example, an override may forward `WISHD_BASE_URL: ${WISHD_BASE_URL}`.

| Compose setting | Default |
|---|---|
| `WISHD_BIND` | `127.0.0.1` (gateway only; `DATASPINE_BIND` also accepted) |
| `WISHD_PORT` | `8080` (`DATASPINE_PORT` also accepted) |
| `WISHD_PG_BIND` | `127.0.0.1`, independent of the gateway |
| `WISHD_PG_PORT` | `5432` (`DATASPINE_PG_PORT` also accepted) |
| `WISHD_POSTGRES_PASSWORD` | `dataspine`, for local demo use only |

Set a strong, URL-safe `WISHD_POSTGRES_PASSWORD` **before initializing a new shared database**.
Changing this value later does not change a password already stored in the Postgres volume;
rotate the database role's password and update all connection strings together. Do not delete
a volume to fix a login problem. Keep the Compose project name stable when upgrading.

Use `docker compose config --quiet` to validate settings without printing resolved secrets.
After `make up`, the CLI's database URL points at the published local Postgres port. Custom database ports from `.env` are included in that URI. Set `GATEWAY_URL` for
`make demo` when using a custom gateway port.

## Spark capture hygiene

The supplied Spark development stack and EMR bootstrap extend Spark's redaction pattern
to include `apiKey`. The default pattern does not cover OpenLineage's token property.
Set the same pattern in your own Spark deployment before capturing event logs:

```text
spark.redaction.regex (?i)secret|password|token|access[.]?key|api[._-]?key
```

Inspect and sanitize captures before sharing them even with redaction configured. For EMR,
prefer `--token-file` pointing at a securely provisioned file on the cluster; bootstrap
arguments and Spark configuration can themselves be visible to platform operators. The
bootstrap remains unvalidated on a real EMR cluster.
